Proposed approach / Microsoft Azure

From study evidence.
To review-ready reports.

Populate the GLP toxicology Word template from study documents. Use focused AI agents for language tasks, code for verifiable operations and the study director for scientific judgment and approval.

1. One evidence-led authoring workflow

Extract source text and tables, confirm the evidence, then populate approved template sections. Every generated statement needs source support; missing information becomes an author item, not a guess.

Extract documents→Check evidence→Draft & validate→Review & export Word

2. Agents decide. Tools execute.

Keep the evidence-bound writer for section drafting. Add four focused roles for template setup, fallback retrieval, critique and dependent sections. Code checks their outputs; people approve the required decisions. Tool names below are proposed interfaces, not deployed integrations.

DESIGN TIME

Contract authoring agent

Read a new template and its colour legend. Propose tasks, evidence rules and writing instructions. A person reviews the contract before use.

Tools: template_mapping contract_schema validate_contract
WHEN RULES FIND NOTHING

Search fallback agent

Search the authorized study's page index when headings or document types are unfamiliar. Propose evidence for gate checks and human approval; never approve it itself.

Tools: search_pages get_evidence propose_evidence
AFTER EACH DRAFT

Critic agent

Check completeness, tense, standard sentences and excluded content. Return exact findings for one corrective retry within the shared call limit, then flag an author item.

Tools: template_rules validate_draft redraft_task
AFTER SECTION APPROVAL

Dependent-sections agent

Draft Summary and Conclusion only from approved sections in each Include list. Code builds contents and references. Changed inputs invalidate dependent drafts.

Tools: approved_sections known_values validate_draft
DETERMINISTIC CORE

Planner and tools

Keep classification rules, evidence locations, known values, table copying and rendering in code. Agents call these tools; they do not replace them.

Core: evidence_planner table_copy renderer
AUTHOR OF RECORD

Study director

Write judgment-based sections, resolve author items and approve uncertain evidence and drafts. Final signing stays in the approved document system, not the agent workflow.

Code stays in control. Use deterministic tools for in-scope table copying, calculations, citation checks and Word formatting. Exact-copy completeness checks must be implemented and validated before verbatim sections are accepted.

3. Follow a fixed workflow

Use Microsoft Agent Framework for orchestration, with tracing for tool and model calls. Proposed hosting: Azure Container Apps, or an adapted Foundry hosted agent.

  1. 01 / Sequential

    Plan the study

    Extract, check evidence, classify documents and locate source pages for each task.

  2. 02 / Fallback

    Fill evidence gaps

    Search only when rules find nothing. Check and approve proposed evidence before use.

  3. 03 / Concurrent

    Draft and copy

    Run independent drafts, values and table tasks within the shared call limit.

  4. 04 / Check

    Review the drafts

    Run validators and the critic. Allow one bounded corrective retry, then author review.

  5. 05 / Sequential

    Combine and render

    Build dependent sections from approved inputs, validate again and produce the Word review copy.

Why not one autonomous agent? Bounded steps make evidence selection, decisions and failures easier to audit. Retrieve the pages needed for each task instead of sending entire study packages to a model.

4. Use Azure for the right job

Azure serviceWhat it does
Blob StorageKeep source documents and generated drafts in private storage.
Azure AI Content UnderstandingPrimary extraction route: text, tables and document structure from PDFs.
Azure AI Document Intelligence LayoutComparison and optional second extraction engine for OCR, layout and tables. Select it for evaluated cases; outputs still pass the same evidence checks and review.
Microsoft FoundryProvide model deployments for drafting and agent reasoning; optionally host an adapted agent workflow.
Azure AI SearchStore one indexed record per source page. Support fallback retrieval and author questions; deterministic page-location rules remain the primary route.
Container AppsHost the fixed Agent Framework workflow and authenticated review API or UI.
Entra ID & Application InsightsControl access and monitor runs, failures and model calls without logging document content.

These are proposed service roles, not a deployed system. Confirm subscription, regional availability, permissions and costs before provisioning.

5. Keep the author in control

  • Body-weight, physical-exam and clinical-pathology Results tables stay author-only. GLP impact statements come from the study director.
  • Follow confirmed customer rules: for Summary, red instructions override green highlighting. Copy the protocol archival statement only when an in-scope external report has none; otherwise add nothing.
  • Missing sources or unresolved rules block the affected task. Final reports are comparison references, never generation inputs.

Start small: strengthen the existing checks, pilot the draft-review agent, then test evidence search on an unseen study. Measure accuracy, cost and author review time before expanding.

Path to production

Four steps to production readiness

Validate each step before expanding. Use finalized reports as comparison references only, never as agent inputs.

STEP 1 / NEXT

Deterministic coverage

  • Verbatim copying with completeness checks.
  • Remaining personnel, Table 2.1 and data-system tables; extend and retest existing QA copying.
  • In-scope study-design, mortality and clinical-signs evidence.
STEP 2

Critic and dependent sections

  • Check each draft against its instructions.
  • Draft Summary and Conclusion from approved sections.
  • Build contents and references with code.
STEP 3

Fallback and blind test

  • Find evidence in unfamiliar document families.
  • Run on a third, unseen study package.
  • Measure missed evidence, false matches and review effort.
STEP 4

Production hosting

  • Container Apps workflow, managed identity and private networking.
  • Reviewer interface for author items and approvals.
  • Contract authoring agent for new templates.

Release gates: agreed accuracy and completeness, no evidence-gate bypass, successful unseen-study testing, then operational and quality-team approval. Scope and acceptance criteria are agreed before each phase.

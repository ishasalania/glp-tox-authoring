04
Agents at defined points

Agents decide, tools execute

Proposed roles, not deployed agents. Runtime drafting uses approved evidence; the Search agent may inspect authorized candidate pages but cannot approve them. Tool names below describe proposed interfaces.

Design time

Contract authoring agent

Reads a new template version and its colour legend and proposes the task contract: blocks per task, where evidence is found, how it is written. A person reviews it before use.

template_mapping contract_schema validate_contract
When rules find nothing

Search fallback agent

For unknown document families or sections without a predictable heading, it searches the page index, checks the document and heading, and proposes evidence for approval.

search_pages get_evidence propose_evidence
After every draft

Critic agent

Checks form, completeness, tense and exclusions. Findings share the existing one-retry and call budget, then become an author item; no extra unbounded retry loop.

template_rules validate_draft redraft_task
Dependent sections

Dependent-sections agent

Drafts Summary and Conclusion only from approved sections in each Include list. Code builds contents and references. Source changes invalidate dependent drafts.

approved_sections known_values validate_draft
Deterministic core

Planner and tools

Keep classification rules, locate rules, known values, supported table copying and rendering in code. Add deterministic verbatim copying with completeness checks next.

evidence_planner table_copy renderer
Author of record

Study director

Writes judgement sections, resolves author items and approves evidence and drafts. Final signing stays in the approved document management system.

Reviewer interface and approval workflow require cloud implementation
05
Orchestration

A fixed workflow with judgement inside each step

Microsoft Agent Framework coordinates each step. Use Azure Container Apps for hosting and Foundry for models; Foundry hosted agents are another runtime option. Deployment is proposed.

Sequential

Plan the study

Extract, gate evidence, classify documents and locate pages for every task.

Fallback

Fill evidence gaps

Search fallback proposes authorized candidates; evidence gate checks and human review apply before use.

Concurrent

Draft and copy

Known values, tables and parallel drafts run at once within the call limit.

Maker and checker

Critic review

Run validators and critic; one shared corrective retry, then author review.

Sequential

Dependent sections, render

Summary and Conclusion from approved sections; validate again, then render the Word review copy.

Why not one autonomous agent

Small, controlled steps make sources, decisions and failures easier to review. Retrieve only the pages each task needs; validation does not replace scientific review.

06
Trust and GxP

Keep evidence and decisions reviewable

Validate evidence checks, approvals and audit records against the agreed requirements. These controls do not establish GxP or 21 CFR compliance on their own.

Evidence gate

Text-layer confirmation can approve eligible pages; unconfirmed scans need human review. Agreement with an OCR-generated text layer is not independent proof of accuracy.

Exact quotes

Every model claim must quote approved evidence exactly, and every number must appear in those quotes. Wrong citations are rejected.

Preserve the template

The PoC checks untouched content and targeted output by readback. This is not a guarantee of byte-identical DOCX files or identical visual layout on every page.

Identity and authorization

Use Entra authentication, workload identities and study-level authorization. Separate agent identities and acting on behalf of a user require explicit configuration; neither happens automatically.

Final reports stay reference only

Finalised reports are used only to measure results, never as extraction, prompt or drafting input.

Unsupported-content checks

The repository reports none found in its two-study review, not a guarantee. Missing facts become author items; an unseen study remains necessary to test generality.

Production adds private endpoints, VNet-integrated compute, document-level authorization in Search, retention policies and logging without document content.

Path to production

Four steps to production readiness

Each step is measured against the finalised reference reports before the next one starts.

Step 1 · Next

Deterministic coverage

  • Verbatim sections with completeness checks
  • Remaining personnel, Table 2.1 and data-system tables; extend existing QA copying
  • In-scope study design, mortality and clinical signs evidence
Step 2

Critic and dependent sections

  • Critic agent on every draft
  • Agent-drafted Summary and Conclusion; code-generated contents and references
Step 3

Fallback and blind test

  • Search fallback agent for unknown document families
  • Blind run on a third, unseen study package
Step 4

Production hosting

  • Container Apps workflow, managed identity, private networking
  • Reviewer UI for author items and approvals
  • Contract authoring agent for new templates
